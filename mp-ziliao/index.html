P-01 · 小程序

个人资料

新用户注册后补齐资料。八项里只有姓名必填，其余可空着保存，也可以直接跳过。

1 · 功能点
  • 展示八项：头像、手机号（只读）、姓名、性别、生日、所在地、详细地址、初次养宠时间。
  • 姓名保存后锁定：再进入只读，右侧显示锁图标。
  • 头像三种来源：微信头像、相册、拍照。
  • 所在地三级联动，详细地址定位带出后手补门牌。
  • 跳过不写库，提示条换文案后进首页。
2 · 交互与联动
  • 点头像行弹三个选项，选中即回填；遮罩、取消、ESC 都能关。
  • 点手机号行无响应：无箭头、无按下态。
  • 姓名为空时是输入框，保存成功后转只读，箭头换成锁。
  • 性别单选，点已选的一侧不取消。
  • 生日与初次养宠时间弹三列日期，未来日期置灰。
  • 姓名空着点保存：行描红 + 红字提示 + toast，焦点回输入框，不发请求。
  • 点跳过：提示条换文案 + toast，不跳转、不写库。
3 · 数据来源与刷新
  • 进页面取 GET /v1/users/me，八项一次带回，模板直出。
  • 头像 POST /v1/upload 拿 url 只做预览，保存时一起提交。
  • 地区树 GET /v1/address 首次点开时拉取，页面内缓存。
  • 定位用 wx.getLocation + 逆地理，成功回填省市区；失败只 toast。
  • 保存 PUT /v1/users/me，只提交改动过的键，不回读。
4 · 字段取值逻辑

取数链路：进页面 GET /v1/users/me → 读 rc_users 单行。门店档案本页不涉及。

客户主档rc_users按登录态 uid 取单行
  • 姓名rc_users.real_name接口出参 real_name；空可改，有值只读
  • 性别rc_users.sextinyint：0 女 / 1 男；空则不预选
  • 生日rc_users.birthdatedate，按 YYYY-MM-DD 展示；默认 1990-01-01 视为未填
  • 所在地rc_users.province_id / rc_users.city_id / rc_users.district_id三列 id 拼成省·市·区；任一为空即未选
  • 详细地址rc_users.streetvarchar，定位回填后可改；可空，超 100 字截断
  • 初次养宠时间rc_users.first_pet_adoption_datedate；等于注册当天默认值视为未填
  • 头像rc_users.avatarupload 返回的 url；空则显示相机占位
只读身份rc_users同上单行，不给入口
  • 绑定手机号rc_users.phone_number注册时微信授权写入；只读，换号走另一页
  • 微信身份rc_users.unionid不展示、不提交；只用于判重与推送
5 · 判定逻辑
  • 姓名留空点保存→ 行描红 + 红字 + toast，停在原页，不发请求
  • 姓名有值点保存→ 提交改动；成功转只读，提示条与跳过隐藏
  • 姓名已锁再进入→ 只读，点该行无响应
  • 其余七项全空点保存→ 允许通过，只写姓名
  • 点跳过→ 不发写请求，只换提示条并放行
  • 生日选到未来→ 该日不可点
6 · 业务规则
硬约束
  • 姓名必填且保存后不可改：前端只读，后端见到已有 real_name 即丢弃该字段。
  • 手机号本页不可改：无入口无箭头，换号是另一条链路。
  • 跳过不写库：不留半条记录，下次进入仍是空表单。
数值口径
  • 姓名 2–20 字；生日不晚于今天；详细地址不超过 100 字；日期统一 YYYY-MM-DD。
例外与收敛
  • 老用户已有姓名：直接进只读态，不出现「请填写姓名」。
  • 定位失败或无权限：地址留空可手填，不影响保存。
  • 保存失败：已填内容全保留，toast 提示重试。
需求原文（节选）

§2.2 字段表（节选） 姓名必填、未填可填填过即锁；性别/生日/所在地/详细地址/初次养宠时间/头像非必填；手机号只读。

§2.3 规则（节选） 非必填项可不填保存；姓名保存后不可改；跳过不校验不写库；只更新提交过的键；失败保留已填内容。

7 · 状态与可操作
初始（新用户）

看到提示条 + 八行空表单 + 跳过与保存

能做任意填、可跳过、可保存

姓名未填

看到姓名行描红 + 红字 + toast

能做补填后重新保存

姓名已锁定

看到姓名只读带锁，提示条与跳过消失

能做只能改其余七项

已跳过

看到提示条换文案，跳过按钮隐藏

能做回首页；下次进入仍是空表单

P-02 · 小程序

添加萌宠

新增一只宠物。五必填（品种、昵称、生日、性别、绝育）加种类，四项选填，保存即写入宠物档案。

1 · 功能点
  • 选种类：猫 / 狗 / 异宠 三张卡单选，切换即刷新品种。
  • 选品种：弹层按当前种类列品种。
  • 填昵称、体重、生日、性别、绝育、毛色、头像。
  • 保存时一次校验全部必填，缺项逐行标红并汇总提示。
2 · 交互与联动
  • 点种类卡：橙描边 + 「已选」角标，切换会把已选品种清回未选。
  • 点品种行弹列表，选中回填文本并去掉灰态。
  • 昵称行内输入 1–20 字，输入即清掉该行报错。
  • 体重失焦即校验格式，不等保存。
  • 生日弹日期，不允许未来。
  • 性别弟弟 / 妹妹单选；绝育是 / 否单选，初始都不选中。
  • 缺项点保存：缺的行描红 + toast 列出缺项，停在原页。
  • 保存成功：toast 提示，停留本页可继续新增。
3 · 数据来源与刷新
  • 品种字典 GET /v1/pet-breeds?category=，按种类过滤，同种类不重复请求。
  • 毛色字典 GET /v1/pet-coat-colors 全量拉一次，页面内缓存。
  • 头像 POST /v1/upload 返回 url 只做预览。
  • 保存 POST /v1/pets 一次提交全部已填字段，成功后本地插入列表。
4 · 字段取值逻辑

取数链路：本页只写 rc_user_pets 主档，user_id 取登录态；字典表只读不写。

宠物主档rc_user_petsuser_id = 登录用户 id，新增插一行
  • 种类rc_user_pets.categorytinyint：1 猫 / 2 狗 / 3 异宠；必须选中，保存后不可改
  • 品种rc_user_pets.breed_id / rc_user_pets.breed_nameid 存字典主键，name 冗余快照；必填；字典没有时可只存 name
  • 昵称rc_user_pets.nicknamevarchar(255)，页面限 20 字；trim 后为空即拦
  • 生日rc_user_pets.birthdatevarchar(15)，本次统一写 YYYY-MM-DD；必填，不晚于今天
  • 性别rc_user_pets.sextinyint：0 弟弟 / 1 妹妹；必选，只两值
  • 绝育情况rc_user_pets.is_neuteredtinyint：0 未绝育 / 1 已绝育；必选且无默认，保存后不可改
  • 毛色rc_user_pets.coat_color_id读 rc_pet_coat_colors 主键；选填，保存后不可改
  • 体重rc_user_pets.weightdecimal(8,2)，单位 kg；选填，填了要 0.1–99.9
  • 头像rc_user_pets.avatarupload 返回的 url；选填，空则列表显默认剪影
字典（只读）rc_pet_breeds / rc_pet_coat_colors品种按 pid 归到种类；毛色独立表
  • 品种列表rc_pet_breeds.name按 category 过滤，母库 921 条；异宠下是通用六项，不细分
  • 毛色列表rc_pet_coat_colors.name全量拉取；不许用户自造，缺的由后台维护
5 · 判定逻辑
  • 没选种类点品种行→ 品种行灰态不可点
  • 切换种类且已选品种→ 品种清空并标红，提醒重选
  • 绝育未选点保存→ 绝育行描红并计入缺项
  • 体重填 4.25 或 120 或 abc→ 体重行描红 + 格式提示，不提交
  • 缺 N 项点保存→ 逐行描红 + toast 列出缺项，停在原页
  • 必填齐、体重留空→ 允许保存
6 · 业务规则
硬约束
  • 种类、品种、绝育、毛色保存后不可改：前端锁，后端 PUT 白名单直接丢弃这四列。
  • 绝育必须显式选，不给默认值：母库该列默认 1，不预选也不兜底。
  • 性别只有弟弟 / 妹妹两值，不引第三种。
数值口径
  • 体重 0.1–99.9 kg 最多一位小数；昵称 1–20 字；生日精确到日且不晚于今天。
例外与收敛
  • 品种字典没有的品类：只写品种名文本，不阻断保存。
  • 异宠品种是通用六项，不做物种细分。
  • 上传失败：头像留空，其余照常保存。
需求原文（节选）

§3.2 字段表（节选） 必填：种类、品种、昵称、生日、性别、绝育；选填：毛色、体重、头像。种类三 tab 含异宠。

§3.4 校验（节选） 缺项逐行标红加汇总提示；体重 0.1–99.9 一位小数；生日不晚于今天。

7 · 状态与可操作
初始

看到三张种类卡 + 八行表单，绝育两项都不选中

能做自由填写、切种类、保存

缺项标红

看到缺的行描红 + toast 汇总

能做补填后重存，已填内容不丢

已保存

看到toast 提示，表单保持刚才的值

能做可继续新增；改它要走编辑页

P-03 · 小程序

编辑宠物

已保存宠物的编辑页。种类、品种、绝育、毛色四项锁死，只放开昵称、生日、性别、体重、头像。

1 · 功能点
  • 展示全部字段：四项锁定值置灰带锁，五项可改。
  • 可改五项：昵称、生日、性别、体重、头像。
  • 保存只提交可改字段，锁定四项不进请求体。
2 · 交互与联动
  • 点种类卡无响应：降饱和 + 「不可改」角标。
  • 点品种、绝育、毛色行无响应，行尾显示锁图标。
  • 昵称、体重、生日、性别与新增页规则一致。
  • 点保存 toast 提示只提交可改字段，停留本页。
3 · 数据来源与刷新
  • 进页面取一次详情，带回全部字段，锁定四项只用于展示。
  • 保存 PUT /v1/pets/{id}，请求体只带五个可改键。
  • 头像 POST /v1/upload，替换后随保存提交。
4 · 字段取值逻辑

取数链路：一条记录来自 rc_user_pets 单行（id + 登录 uid）；锁定四项读出只展示，请求体剔除。

锁定展示（不提交）rc_user_pets按 id + user_id 单行
  • 种类rc_user_pets.category1 猫 / 2 狗 / 3 异宠，映射到卡片选中态；只读，后端丢弃
  • 品种rc_user_pets.breed_name读冗余快照，字典改名不影响展示；只读，id 与 name 都丢弃
  • 绝育情况rc_user_pets.is_neutered0 未绝育 / 1 已绝育，渲染成文字；只读，不可回退
  • 毛色rc_user_pets.coat_color_id查字典取名展示；只读，后端丢弃
可改（提交这五个键）rc_user_pets同上单行
  • 昵称rc_user_pets.nickname行内输入 1–20 字；空则拦
  • 生日rc_user_pets.birthdateYYYY-MM-DD，不晚于今天；非法日期拦在本页
  • 性别rc_user_pets.sex0 弟弟 / 1 妹妹；单选，不可取消
  • 体重rc_user_pets.weightdecimal(8,2)，kg；可空；填了 0.1–99.9
  • 头像rc_user_pets.avatarupload 返回的 url；可空
5 · 判定逻辑
  • 点锁定四行→ 无反应，不弹提示
  • 昵称改空点保存→ 昵称行描红 + toast，不提交
  • 体重格式非法→ 体重行描红 + 格式提示，不提交
  • 只改体重点保存→ 请求体只带 weight 一个键
  • 什么都没改点保存→ 允许，toast 提示，不产生脏写
6 · 业务规则
硬约束
  • 种类、品种、绝育、毛色保存后不可改：前端只读，后端白名单剔除，不靠隐藏当边界。
  • 本页不放删除入口：删除要满足无进行中预约。
  • 改品种与绝育只走后台管理端，C 端无入口。
数值口径
  • 昵称 1–20 字；生日不晚于今天；体重 0.1–99.9 kg 最多一位小数。
例外与收敛
  • 历史生日只有年月：按当月 01 日展示，不改则原值保留。
  • 落库品种名与现字典不一致：以快照展示，不强行纠正。
  • 体重为空的老档案：显示未记录，不显示 0.00。
需求原文（节选）

§3.3 不可改的落地（节选） 三层：前端只读（灰化加锁）/ 后端白名单丢弃 category、breed_id、breed_name、is_neutered、coat_color_id / 要改走后台。

7 · 状态与可操作
锁定态

看到种类卡灰化保留选中色 + 「不可改」角标；品种、绝育、毛色置灰带锁；其余五项正常

能做改五项后保存；四项不可操作
