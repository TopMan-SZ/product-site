一句话读懂这条链：HIS 发一条事件，服务端按受众拆成 1～2 条通知，各自取模板、选通道、投递，最后按任务回调结果。

读法：从上到下是角色（接入方 / 后台管理员 / 消息服务 / 收件人），从左到右是业务推进的九步；九步分两带画（①—⑤ 主链、⑥—⑨ 收尾），下一带接着上一带的出口，中间的横线就是接续处。 点任意带页面的方块跳到对应页面，右侧同步定位到这一页的说明。判断节点（凭证有效、事件码已登记、这条开着、有模板、回执哪一类）的每条出边都带条件。

  1. 打开事件目录，母事件默认全部展开
  2. 展开一条子事件，看码、发起方、类型、受众、模板、时点
  3. 点母事件行，收起或展开这一组
  4. 按母事件、类型、受众或关键字筛
  5. 切「群发事件」，只看临时通知能选用的那几条
  6. 在状态列点开关，停用或启用这一条

4规则

  • 注册只有一条路：研发写处理器并登记，后台不新增
  • 登记七项，缺一项不上线：码、类型、受众、模板、时点
  • 含员工的还要定默认角色与可选通道，缺了不上线
  • 码全局唯一，重复注册直接构建失败，上线后不改
  • 母事件按码前缀归组，没有状态，也没有配置
  • 一次注册只落一条子事件，一个码就是一条
  • 受众再拆：客户一条、员工一条、双发就是两条
  • 事件码：契约标识，研发定，页面上改不了
  • 类型：业务事件或群发事件，只有群发能被临时通知选
  • 受众：客户、员工、双发；双发就是各来一条
  • 默认模板：每个受众按通道各一份，这里只看不改
  • 默认时点：立即，或事件后几小时；医院可覆盖
  • 状态：启用或停用，停用不删，随时能开回来
  • 注册后运行时只三步：认码、拆受众、取谁的覆盖

6验收场景

  • 如果拿一个没注册的码来发，应该直接拒绝，不生成任务
  • 如果停用一条子事件，再来事件不该生成任务
  • 如果点母事件行，只该影响显示，不改任何状态
  • 如果找模板编辑入口，页面上应该没有

3怎么操作

  • 已生成的任务按当时的值走完，不追改
  • 每次保存记谁、何时、改了哪项、前后值
  • 能进本院就能配本院，集团账号看全部院
