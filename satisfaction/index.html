满意度调查系统 - 产品需求文档（PRD）

版本 V1.0 ｜ 配套原型：本文件"问题库管理 / 模板管理 / 调查明细 / 推广二维码"四个页签 ｜ 适用读者：开发、测试、评审

一、背景与目标

现状问题：旧系统中调查模板只能在数据库里直接维护，模板不与医院进行绑定，推广生成；题目类型仅支持单选、问答、评级三种；医院推广时逐医院生成二维码；调查结果只能在调查明细中逐条查看，缺乏统计汇总，工作人员无法快速了解整体满意度。

重构目标：

  1. 问题库独立维护：题目集中管理、分类（诊疗类 / 服务类 / 吐槽类）、可跨模板复用，记录使用次数。
  2. 模板独立维护：模板与医院解耦，通过"关联医院/品牌"配置；可自由从问题库选题，也支持模板内手动添加自定义题。
  3. 条件化问题展示：模板内可配置"问题依赖"，按前一问题答案决定是否显示/跳过后续问题，提升问卷精准度。
  4. 结果可统计可明：调查明细按医院/模板汇总，评分类题目展示平均分与分布，支持按题查看明细，工作人员一目了然。
  5. 推广简化：按医院/品牌选择后一键生成二维码，二维码直接关联到具体模板。
  6. 诊疗后自动触达（新增）：医院可在后台"综合配置"开启自动下发，HIS 诊疗结束后自动通过微信模板消息（短信兜底）把满意度调查链接推送给宠主，无需患者主动扫码。

二、角色与权限

角色说明可用功能
管理员集团管理员全部功能：问题库、模板、明细统计、二维码生成、医院下发配置（含跨品牌批量同步）
品牌/医院工作人员门店端使用查看本院调查明细与统计、推广本院二维码、配置本院下发（仅本院，同步范围限本院归属医院∩权限医院）
患者（C端）扫码/收推送填写者填写问卷（扫码或微信/短信推送链接进入同一 C端页面）
HIS 系统外部调用方（机器）诊疗结束时调用 POST /open/his/survey/push 触发下发判断与推送；HMAC 签名鉴权，仅能查询/触发，不能改配置

三、核心业务流程图

3.1 管理主流程（配置侧）

维护问题库→ 创建/编辑模板→ 关联医院/品牌→ 配置问题及依赖→ 校验通过？
否 → 按校验提示修正是 ↓
→ 保存模板→ 推广生成二维码

3.2 填写与查看流程（数据侧）

患者扫二维码→ C端按依赖逻辑展示题目→ 提交答卷→ 明细入库+统计更新→ 工作人员查看明细/统计

C端两条入口汇入同一填写页：① 扫"推广二维码"（线下主动入口）；② 诊疗结束自动下发的微信模板消息/短信链接（HIS 触发入口）。两条入口指向同一 /survey/{qrId}，统计口径统一，仅来源渠道不同（可后续在 s_survey 加 source 字段区分扫码/推送，本期不做）。

→ 模板启用？

是 → DUPLICATED 结束否 ↓

四、功能模块说明

4.1 问题库管理

业务说明：集中管理所有可复用题目。模板创建时优先从问题库选题，保证口径统一、便于横向统计对比。

  • 分类：诊疗类（紫）/ 服务类（蓝）/ 吐槽类（橙），新增/编辑时必选，用于模板组织与统计分组。
  • 题型：评分题（1~5星）、单选、多选、问答（文本题）。单选/多选需配置选项（2~10个）。
  • 使用次数：统计该题被模板引用的累计次数；若题已被模板引用（使用次数>0），删除时给出警告（见 4.2 校验规则）。
  • 批量导入/导出：Excel 模板导入（字段校验：分类/题型/选项必填），支持导出当前筛选结果或全量。

4.2 模板管理

业务说明：模板 = 一组有序题目 + 依赖规则 + 关联医院/品牌。旧系统中"模板不关联医院"的结构升级为"一模板多医院"，医院按品牌/单店粒度挂载。

  • 模板列表：编号、名称、题目数、填写次数、综合评价（平均分）、关联医院、状态、创建时间；操作：编辑 / 问题配置 / 明细 / 推广 / 启停 / 删除。
  • 模板编辑（模板信息）：模板名称、关联医院/品牌（树形多选，品牌节点勾选后其下医院默认继承但可单独取消）、备注。独立于问题配置，降低操作心智。
  • 问题配置（问题列表）：左侧题目列表支持：从问题库添加（按分类/题型筛选）、手动添加（模板自定义题，不入问题库）、上移/下移排序、删除。右侧依赖配置。
依赖配置规则（重点，页面右侧逐题展示）：
  1. 条件句式：当【选择问题】答案等于【选择题的答案/星级】时，【显示 / 跳过】该问题，末尾附【删除】按钮。问题与答案均为下拉选择，不可手填。
  2. 答案下拉内容随所选题型联动：评分题 → 1~5星；单选 → 该题选项；多选 → 该题选项（语义为"包含"）；问答 → 无内容/有内容。
  3. 该题已有条件 → 只展示条件行与删除按钮，不再显示"添加条件"（一个题只允许一条条件，避免逻辑嵌套）。
  4. 该题无条件，且不是第一条、不是最后一条 → 显示「+ 添加条件」按钮。
  5. 第一条题不允许配置依赖（无前序答案可判断）；最后一条题通常作为兜底建议题，不展示添加入口。
校验与提醒（保存模板前必须通过）：
  • 模板至少 1 道题目，否则提示"模板暂无题目，请先配置"。
  • 依赖的父问题被删除/移出模板 → 自动清除该条件并 toast 提醒"问题X已移除，其依赖条件已清除"。
  • 所选答案值与父题当前选项不一致（如父题选项被改）→ 保存前提示"问题X的选项已变更，请重新选择答案值"。
  • 评分题条件答案必须为 1~5 星之一；单选/多选的"答案"必须是父题现存选项。
  • 删除被引用题目（问题库侧）→ 二次确认弹窗，展示引用它的模板列表，确认后自动从各模板移除并清理相关依赖。
  • 模板删除前检查：存在历史答卷或启用中的二维码 → 提示"建议停用而非删除"，删除为软删除，历史明细保留。
  • 模板停用强提醒（新增）：停用操作弹二次确认，文案："停用后，所有已开启下发的医院将自动暂停推送，请确认。"；停用后 t_org_survey_config 中配置保留不改写，下发判断接口联查模板状态返回 NOT_READY（自动暂停）；模板重新启用且该医院配置在停用期间未变更（update_time 不变）→ 自动恢复下发，无需人工操作。

4.3 调查明细

业务说明：将"逐条翻答卷"升级为"先看汇总、再钻明细"。分两层：

  • 统计层（默认展示）：筛选维度 = 时间范围 + 医院/品牌 + 模板；展示卡片：总填写次数、综合平均分。下方按模板×题目列出每道题的平均分（评分/题）。
  • 明细层：点击某道题可下钻到具体答卷列表（答卷ID、医院、提交时间、该题答案）；也可从答卷维度查看完整答卷（含被跳过的题标记为"未展示"）。
  • 导出：支持导出统计结果与明细列表（Excel）。

4.4 推广二维码

  • 医院选择（二级联动、单选）：表单提供「品牌 → 医院」两级下拉——品牌仅作筛选维度，不可被选中生成；实际按所选医院生成二维码。选择品牌后医院下拉联动刷新为该品牌下的医院；改回"全部品牌"则列出全部医院。医院为单选，生成时必须有且仅有一个医院。
  • 选择 医院 + 该医院可用模板 → 生成二维码，编码内容为带模板ID与医院ID的C端URL（如 /survey/{qrId}）。
  • 同一"模板+医院"组合仅保留一条有效二维码记录。
  • 重复选择生成，复用已生成二维码。

4.5 宠主端（C端填写页，小程序）

业务说明：宠主扫码或从小程序进入填写页。UI 设计见本文件"宠主端UI设计"页签（填写页/依赖跳过/成功页/异常态四类界面）。与旧版差异：题目与依赖关系不再写死在页面，全部由模板快照 + 依赖配置驱动。

  • 进入校验：按 qrId 加载 → 校验码状态（停用→"问卷已下线"页；过期→"已过期"页；正常→进入填写）；再校验幂等（同 qrId+client_id 已提交→"您已参与过"页）。
  • 题目渲染：加载模板全部题目（按顺序），逐题判断依赖：存在条件且父题答案命中 → 按显示/跳过动作处理；无条件默认展示。被跳过的题不渲染、不要求作答。
  • 题型控件：评分题 1~5 星点选；单选互斥；多选可多项；问答多行文本（选填/必填按模板配置）。
  • 提交：可见题目必答校验通过后可提交；提交成功跳成功页并展示"3秒后跳转小程序首页"；提交动作异步写入答卷与答案明细（被跳过的题写 skipped=1 记录）。
  • 防重提交：提交中禁用按钮防连点；服务端按幂等键兜底拒绝重复。

4.6 医院下发配置（医院管理 · 综合配置，新增）

业务说明：在现有后台"医院管理"列表为医院增加"综合配置"能力——配置该院诊疗结束后是否自动下发满意度调查、下发哪个模板。HIS 诊疗结束（HIS 侧行为）时调用本系统接口判断并推送，本系统不改造 HIS。下发链接复用"推广二维码"产出的 医院×模板 有效码（两者互不影响：扫码是线下主动入口，自动下发是诊疗后触达入口）。

  • 配置项：① 是否开启自动下发；② 下发模板（单模板）；③ 推送渠道：微信模板消息（优先）+ 短信兜底；④ 同步到其他医院（批量）。
  • 可选模板范围：该院的归属模板（t_template_org 命中）且模板启用。未归属模板不展示、不做拦截提示。
  • 同步范围限定：同步目标 = 该模板归属医院 ∩ 当前操作角色有权限的医院。例：角色有权限 a/b/c，模板归属 a/b/d → 配置 a 院时只能同步给 a/b（d 因权限不可见，c 因非归属不展示）。同步为批量写入，逐院校验、整单事务，部分失败返回逐院原因可重试。
  • 推送链路：HIS 诊疗结束 → 调 POST /open/his/survey/push（orgId+billId+clientId/phone）→ 判断开启/模板状态/去重窗口（同院同宠主 24h 一次）→ 取有效码短链 → 微信模板消息，失败或无 openid 时转短信 → 写推送日志。返回码语义见技术文档 6.1。
  • 模板停用联动：停用模板时弹强提醒二次确认（"停用后已开启下发的医院将自动暂停"）；下发判断接口实时联查模板状态，停用=自动暂停（不改配置表）；重新启用且配置未变更 → 自动恢复。
  • 推送日志与去重：每次判断/推送写 s_survey_push_log；(orgId, billId) 幂等，(orgId, clientId, 窗口内) 去重，避免连台就诊重复打扰。
与旧版/其他模块的关系：本功能不改"推广二维码"页逻辑（仍按医院生成、品牌不可选、二级联动）；C端填写页完全复用（自动下发的链接与扫码链接指向同一 /survey/{qrId}，统计口径统一）。

七、异常与边界

  • 模板被编辑期间有用户正在填写：C端答卷按提交时的快照作答，统计按答卷提交时的题目快照计算。
  • 答卷提交失败/重复提交：以二维码+设备/用户维度做幂等控制（同组合仅允许一次，可配置是否允许多次）。
  • 二维码长期未扫描：默认有效期 1 年，过期后访问提示"问卷已过期"。
  • 自动下发相关边界（新增）：① HIS 重复回调同一 billId → 幂等直接返回 DUPLICATED，不重复推送；② 微信模板消息失败（额度/拒收）→ 有短信渠道自动兜底，无则记录 PARTIAL_FAILED 可人工重推；③ 宠主无 openid 且手机号缺失/无效 → NO_CONTACT，仅记日志不下发；④ 模板停用期间 HIS 回调 → NOT_READY，HIS 无需重试（模板启用后同宠主窗口内未推送过的可补推策略待运营确认，本期不自动补推）；⑤ 连台就诊（同宠主多张病历）→ 去重窗口 24h 仅推一次，后续单据返回 DUPLICATED。
满意度调查系统 - 技术文档

版本 V1.0 ｜ 内容范围：数据库表设计、字段说明、核心逻辑与接口约定（不含代码）

一、表结构总览

共 7 张表：问题 2 张（题干+选项）、模板 3 张（模板信息、模板-题目关系、题目依赖条件）、答卷 2 张（答卷+答案明细）、推广 1 张（二维码）。医院/品牌复用现有机构表，不做重复设计。

q_question→ q_question_option → t_template→ t_template_question→ t_question_condition → s_survey→ s_survey_answer → p_qrcode → t_org_survey_config→ s_survey_push_log
设计要点：模板题目采用"引用+快照"双轨——t_template_question 存引用（可继续用问题库的题）、同时保存题干/选项/必填标志快照（模板修改与问卷作答不互相干扰）；依赖条件独立成表 t_question_condition，挂在模板题目上（每模板题目至多 1 条，与 PRD 规则一致）；t_org_survey_config 是医院下发开关（一院一行覆盖式更新），s_survey_push_log 记录每次 HIS 触发与推送结果（去重与对账依据）。

二、表结构明细

2.1 q_question 问题主表

字段类型必填说明
idbigint PK是自增
categorytinyint是分类：1诊疗 2服务 3吐槽
titlevarchar(200)是题干，≤100字
typetinyint是题型：1评分 2单选 3多选 4问答
use_countint是被模板引用次数（冗余计数，保存时更新）

idbigint PK自增
question_idbigint, 索引外键→q_question.id
option_textvarchar(50)选项文本，≤20字

约束：同一 question_id 下 option_text 唯一；评分/问答题型无选项记录。

2.3 t_template 模板表

字段类型必填说明
idbigint PK是自增

statustinyint是1启用 0停用
creator / create_time / update_time / deleted—是审计字段，deleted 软删

2.4 t_template_org 模板-医院/品牌关联表

字段类型说明
idbigint PK自增
template_idbigint, 索引外键→t_template.id

2.5 t_template_question 模板-题目关系表（含快照）

字段类型必填说明
idbigint PK是自增，C端按此 ID 标识"模板内的题"
template_idbigint, 索引是外键→t_template.id
sourcetinyint是来源：1问题库 2自定义题
question_idbigint, 可空否外键→q_question.id（仅 source=1 时有值；题库题被删除后本行保留快照仍可展示）
categorytinyint是分类快照
titlevarchar(200)是题干快照
typetinyint是题型快照：1评分 2单选 3多选 4问答
requiredtinyint是必填标志快照：1必答 0选答（默认1；C端"必答"标记与提交前校验依据）
optionsjson否选项快照（数组，单选/多选有值）
sortint是模板内顺序

索引：(template_id, sort)。依赖条件引用的是本表 id（稳定，排序不失效）。required 随模板题目配置写入快照：运营在"问题配置"页可对每道题单独勾选/取消"设为必答"，落库为该题一行快照；题库侧题目默认必填（1），但同一题可被不同模板设为不同的必填态，互不影响。

2.6 t_question_condition 题目依赖条件表

字段类型必填说明
idbigint PK是自增
template_idbigint, 索引是冗余模板ID，便于按模板整体加载
tq_idbigint, 唯一索引是外键→t_template_question.id（被控制的题目，唯一：每题至多1条条件）
parent_tq_idbigint, 索引是外键→t_template_question.id（父题，必须 sort 小于本条）
answer_valuevarchar(50)是匹配的答案值：星级（1~5）、选项文本、"HAS"/"NONE"（问答有/无内容）
actiontinyint是1显示 2跳过
校验逻辑（保存时服务端兜底，与前端规则一致）：① tq_id 唯一 → 一题一条条件；② parent_tq_id 必须指向 sort 更小的题目（非首题才可能有条件）；③ 末题不允许作为被控题（无后续可跳）；④ answer_value 必须在父题快照选项/星级/枚举范围内；⑤ 父题被删除时级联删除本表对应行。

2.7 s_survey 答卷表

字段类型必填说明

字段类型必填说明

三、核心逻辑约定

3.1 C端题目展示判定

加载模板全部 tq（按sort）→ 逐题判断→ 存在条件且父题答案=answer_value？
是 → 按 action 决定展示/跳过否 → 默认展示
→ 提交时写 s_survey_answer（含skipped标记）

无条件的题一律默认展示；"跳过"动作含义：本被控题隐藏，"显示"动作含义：仅在父题答案匹配时展示（否则隐藏）。

3.2 统计计算口径

  • 题目平均分 = AVG(answer) WHERE type=评分 AND skipped=0；选择类 = 各选项计数/总作答数（分母同样过滤 skipped）。
  • 模板平均分 = 该模板全部评分题平均分均值；综合评价 = 全部分类评分题均值。冗余到 t_template.avg_score（提交答卷时增量更新：(旧分×旧次数+新答卷分)/(旧次数+1)）。
  • 统计查询按 (template_id, submit_time)、(org_id, submit_time) 走索引；大时间范围走汇总表（可按需后加 s_daily_stat，本期不做）。

6.2 微信模板消息（调研结论）

调研：官方模板库里没有现成的"满意度调查"模板（微信服务号模板库按 医疗/交通/政务等类目管理，无问卷类目；小程序侧"订阅消息"也无现成问卷模板）。可行方案：选用服务号「工具→活动报名/进度通知」类或「医疗→就诊提醒」类目下的服务提醒类模板，将字段映射为：{{time}}=就诊结束时间、{{thing}}=医院名称、{{phrase1}}="诚邀您对本次诊疗进行评价"、{{url}}=短链（或小程序页跳转参数）。模板消息仅允许服务通知、不得营销化，跳转页面必须是服务号同主体的已发布页面（本次 C端填写页需挂在服务号自定义菜单或关联小程序上，跳转参数走小程序 page 路径）。需与微信侧确认：服务号行业类目、模板 ID 申请（"广告与服务→消息模板"添加）、IP 白名单。短信兜底走现有短信通道，文案含短链。
